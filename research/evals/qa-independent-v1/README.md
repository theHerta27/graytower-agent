## 授权与执行边界

建议新批次固定两题、每题最多 4 次模型决定与 4 场战斗，总最多 **8 次调用、8 场战斗、USD0.25**；只是待授权建议，不是已有额度。父任务须先核算每次 18,000 字符等输入/输出硬上限、协议余量和保守费用，并封存具体外发材料。若正常第二题需要的摘录累积后放不进输入上限，应在运行前明确可支持范围；运行后超限保留失败，不擅自扩大 cap、截掉不利证据或重跑。

新批次只允许这两题的自然目标、常规 QA system/schema、候选 diff/预检/引用、实际 4 场内的配对指标、必要有界 Trace 片段、结构化决定与最新余量。完整仓库、无关文件、Config 确认集、其他真实业务材料和额外解释调用不在此建议内。使用一个新共享持久账本，同时限制每题调用数；失败和未知预留都占额度。旧账本不得重置、复制分支续费；剩余额度不转成第三题、补题或挑选最好一次。

每题首次固定运行并全部保留。prepare 失败、模型失败、工具故障、输入超限或没有完成均留在固定分母 2 中；逐项区分基础设施故障与模型错误。原样保留首次和后续决定，已发现的参数错误或无依据主张不因后来改正而消失。以后若拿结果调 prompt/实现，此包变为已知回归，独立新质量声明另议，不改旧成绩。

## 审阅与判分

评分看完整原话、真实工具结果、收据/原始 rows、所有决定前的余量与账本，不仅看最后 `reason`。结果由单独上下文的独立助手复核，记录 `review_source=independent_assistant`、复核者、逐项原话、文件 hash 与 JSON pointer/行号、理由；真人才标 `human`。题作者/被测模型的自评不算独立复核。缺失复核为 `PENDING_REVIEW`，未运行是 `NOT_RUN`，不得填推测成绩。

| 维度 | 可审阅记录与标准 |
| --- | --- |
| 任务完成 | 按两题各自目标记 complete/partial/not_completed/not_run；A2A 报告交付与语义完成分列。第二题仅答未知却未取得相关事件，边界可能正确，但事件覆盖和任务完成不能记全通过。 |
| 参数与余量 | 保存每次 action/seeds/policies/hash、当时剩余调用/场数及拒绝原因。合法策略仅 balanced/survival/basic_only，版本由工具自动配对；每个新计划消耗 `2×seed数×策略数`，不超过最新余量。准确复用收据不增战斗或 n。报告非法参数、超预算提案次数及首次是否干净，不只看程序拦截成功。 |
| 有效证据 | 核对 candidate/request/job/manifest、seed/policy/variant 与 trace hash 的一致性；只把真实完成收据计作已执行。AV 只比较共同胜利配对，差值是 candidate−baseline；负值只表示该配对用时减少。引用摘录必须写明 variant、seed、policy、事件身份及部分视图范围。 |
| 未支持主张 | 对所有模型 reason 逐项检查：混淆版本、错说方向、片段冒充完整、单版本冒充对照、配置 diff 冒充运行生效、观测冒充因果/总体保证，均记录原句与反证或缺证位置。正确句不抵销矛盾主张。 |
| 实际成本/墙钟 | 每题与总计保存 reserved/completed/failed/unknown 调用、usage、缓存/非缓存、估算费用与未知预留、实际新增战斗。费用估算与账单区分。墙钟从 QA 委托前到报告返回/失败停止，prepare、复核和重放另列，不拿模拟内部时长代替整条链。 |

`cases.json` 定义逐项判据和空白复核结构。逐题“处理正确”只在语义完成、参数/余量合规、有效证据、无未支持主张、预算账实一致且独立复核完整时成立；否则明确失败/部分完成/待复核。费用和时长本身不预设“越少越好”的质量分数，未知调用的费用不记零。只报告这两题的分母与逐项结果，不报告总体成功率。

产品报告仍只允许总体 **FAIL / INCONCLUSIVE**；结构检查 PASS/FAIL/INCONCLUSIVE 单列。结构通过、评测题处理正确、模型 reason 和 A2A completed 都不能把候选总体改为 PASS。遇到确定性失败也可以把它正确报告，业务处理正确不要求候选结果为正。
