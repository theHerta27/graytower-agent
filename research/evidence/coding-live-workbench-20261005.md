## 这次实际完成了什么

研发人员提出：“把击破手的战技倍率从 1.4 调到 1.58，保留战技点消耗、削韧和其他全部配置。”官方 Codex Runtime 通过文件工具读取真实配置、修改文本、检查差异、进行原生 Review，再冻结 Coding 候选。演示操作者确认固定的 auto 候选后，由同一个 A2A Verification 服务独立安排模拟、读取 Trace 并交付报告。

这是配置文件业务链的真实运行，不是任意代码开发或 Unity 验收，也不是协作质量对照。候选未应用或发布到游戏。

## 必须保留的问题

- single 第一次用多行 LF 文本匹配 CRLF 文件，被工具拒绝；主任务随后按唯一单行匹配成功。最终任务完成，但不是全程无工具错误。
- 本批 QA 的四次响应均为合法单个 JSON 决定，没有重现旧双 Decision 协议问题。
- QA 的样本数值解释正确，也限制了小样本结论；但把摘录中的 `break_damage` 与保留击破手 1 SP / 90 削韧说成“方向一致”，证据不足：该事件来自另一角色，摘录没有相关扣点或削韧数值。它随后承认机制证据不足，不能因此把前一句弱关联算作有依据。
- 冻结配置的确定性检查确实证明只改倍率，1 SP 与 90 削韧不变；这与“模型准确完成机制解释”是两项不同结果。后续应补可明确查询配置和机制字段的证据入口，并在新任务确认，不能改写本次回答。

独立开发助手复核为非盲、非真人评分；原始输出、失败和逐项理由在 `local-data/coding-runtime-demo-v1/independent-review.json`。没有为清洗结果付费重跑。

## 工作台实现范围

工作台新增 Coding 任务列表、single/auto 方式、实际自主委派数、修改原文和原生 Review，候选跳转复用原有确认与 QA 页面。模型默认关闭，历史批次仅导入独立展示副本，不能借页面重新开放旧额度。

后端新增单机持久运行记录。同 ID、同输入重复提交只读原操作；不同内容拒绝。启动授权使用精确任务 ID / 原文 / 模式白名单，Responses 账本独立于 Config/QA Chat 额度。页面从服务提供的已授权项选择，不能生成随机 ID 绕开白名单。当前默认 CLI 不提供新的收费 Coding 开关；显式启动适配接口先用本地 fixture 验证。

恢复只处理已有完整 Runtime 收据：重新核对 Review 与工作区完整树，完成未写入的候选记录；没有完整收据或文件已改变时停止，不重新运行模型。没有声称支持 Runtime 任意中断续聊或取消全进程。

本步回归为199项Python测试（197通过、2个既有opt-in跳过）、8项前端测试、TypeScript/Vite构建通过。真实浏览器核对了Coding任务→同一候选→原QA报告；390px窄屏无横向溢出，默认收费按钮禁用。工作台实际HTTP同ID重提复用原结果，新ID在关闭态拒绝，原证据hash未变，0新模型/战斗。截图、API读回及验证记录位于`local-data/coding-workbench-v1/`。M2 整体、代码/build 受限 Worker、动态协作独立质量对照、Electron、Unity 与 NPC 仍按实施路线继续。
