# FastAPI 接口迁移与验收

当前研发助手从 Starlette 应用迁移到 FastAPI，Agent、项目记忆、Git 工作树和 Docker 检查继续复用原实现。旧工作台及 NPC/A2A 实验接口保留原样。

## 接口实际承担的工作

- 为创建任务、运行、恢复、编辑、检查、记忆及交付操作定义严格 Pydantic 请求模型，拒绝额外字段和不正确的类型。
- 对运行授权保留严格布尔类型与业务中的 `is True` 检查，不将字符串或数字转换成同意。
- 返回前端已有的 `error` 格式；校验失败不回显原始输入。保留本机来源检查和 1,100,000 字节正文上限，覆盖分块传输。
- `/docs` 提供可交互文档，`/openapi.json` 声明 25 个路径及真实请求模型。
- 阻塞操作在线程中执行，模型仍沿用原后台驱动。使用独立缓存锁，确保并发首次访问只有一个任务实例，不丢失运行中的检查状态。

实现：[web.py](../../src/agent_workbench/development/web.py)、[请求模型](../../src/agent_workbench/development/api_models.py)、[新增接口回归](../../tests/test_development_fastapi.py)。依赖固定 FastAPI 0.162.0，增加 annotated-doc 0.0.5；已有 Starlette 1.7.0、Pydantic 2.13.5 及其他依赖未升级，`pip check` 通过。

## 验证结果

- 新增 8 项接口回归，覆盖原生 FastAPI/OpenAPI、来源检查、非法输入无副作用、严格授权、组合操作、正文上限、错误格式和并发初始化。先观察旧实现失败，再实现并复测通过。
- 最终 Python 回归清单 445 个唯一用例：441 通过、4 项既有跳过，0 失败、0 错误。四组清单合并检查不重复、不遗漏。
- 前端 36 项测试通过，生产构建通过；接口 URL 与成功响应继续兼容原页面。
- 启动实际 Uvicorn 服务并关闭模型，页面、`/docs` 和 `/openapi.json` 均返回 200，非法 JSON 返回 422 与中文 `error`。
- 在全新临时游戏副本中使用脚本决策和真实 Git/Docker：资源检查先失败，修订后 6 项通过，候选、准备合入结果和撤销结果分别通过 99 项规则检查；原游戏状态未变。

本轮外部模型调用 0 次。Docker 检查和交付探针用于验证工程流程，不新增 DeepSeek 修复效果结论。

## 审查与修正记录

独立审查复现了首次并发读取与检查可创建两个任务对象的问题；单独加缓存锁后，新回归确认只创建一个实例且检查保持 running。详情读取还会使用工作树文件锁，因此回归用记忆读取触发首次初始化，单独检查缓存行为。

保留了首次回归启动脚本缺少项目根路径的导入错误、缓存修复前的失败，以及 Docker 未启动/受限账号无法访问引擎的记录。最后以可访问 Docker 的本机账号重新运行临时副本探针，通过上述完整交付流程。

原始日志位于本机 `local-data/fastapi-migration/`，包括失败、修复、最终清单、真实 HTTP 与 Docker 记录。历史模型实验和旧验收材料没有重写。
