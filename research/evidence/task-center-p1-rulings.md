# P0/P1 实施裁决与后续边界（2026-10-08）

本轮交付统一任务中心与 Config→QA 业务演示；P2 仅完成隔离执行工程预验证，P2/P3/P4 不提前关闭。

## 本轮采用

- Task 是普通业务记录，链接原作者 operation、不可变候选与 QA request，复用既有图、MCP、A2A 和 receipt，不再加一次模型总控。
- 首轮保留已验证的倍率白名单；Boss 血量请求明确拒绝，冲突数值明确澄清。更多字段在 Schema 与规则测试齐备后开放。
- JSON 是权威候选，Excel 从冻结 JSON 确定性导出，文本不作为公式执行；不做 Excel 回传。
- 创建/批准/下载/历史回看不调用模型；批准测试与最终采纳分开。当前演示默认关闭收费调用，已完成批次未用额度关闭。
- 历史数据只读复制关联，旧报告不重算。仅环境指纹变化可进入历史只读视图；引用 Hash、实际冻结配置、Diff 与来源关系仍核对，不能用历史回看绕开新执行检查。
- QA 恢复沿用原准入参数/预算；已完成 Job 按 receipt 对账，未知 Job 拒绝自动重跑。operation 的状态观察按变化追加，不把第二次失败写进同一不可变事件键。
- 历史报告链接与来源事件同一 SQLite 事务；旧半完成链接也按是否拥有 QA operation 判断来源。
- P2 worktree 与容器分别保护编辑目录和执行权限；代码候选必须绑定可信 preparation 的 Commit 和 baseline_tree，补丁在独立目录重建后再运行。
- 端口使用 18783；本机 Docker/WSL 保留段包含先尝试的 8782，不能把绑定失败当应用错误。

## 审查问题处理

五项重要问题均先离线复现，再修复并运行回归：重复失败事件冲突；任务中心缺已准入 QA 恢复入口；历史候选伪造 Diff 导致两种导出不一致；历史链接崩溃后错误标记为新验证；代码候选可替换共同基线并隐瞒额外改动。未追加模型调用来重跑既有质量成绩。

## 明确延后

- 真实 Python Coding Agent 修复、第二个独立 Bug、代码类型 Verification 图/工具/报告、采纳回退：按 P2/P3/P4 继续；人工参考修复不算 Agent 成绩。
- 容器异常路径清理、硬中断资源回收、恶意候选伪造 pytest/XML、逃逸与耗尽负例：当前只做受控自有故障预验证；完成这些负例前不开放任意代码执行，也不作通用沙箱安全保证。
- 当前工程 profile 路径与镜像固定本机；可移植安装与动态 image profile 在正式代码产品交付时补齐。
- 前端重叠轮询/编辑提交竞态、历史观察时间展示、列表性能与专业术语润色：当前演示无重要复现，后续常规优化；观察时间不冒充实际执行时刻。
- 候选批准全局按 Hash、一个 Task 绑定一次不可变 QA 请求：沿用现有 V1 规则。换验收目标或新尝试创建新 Task，不覆盖原报告。
- 自动意图路由、更多配置字段、全实体 Excel、Electron、Unity 自动发布：不阻塞当前纵向链路。
- 协作质量/提速、全面模型质量、跨机器或引擎验收：本轮没有做对应实验，不作结论。

失败保留：P1 harness 初次 factory 参数接错在首个收费调用前修正，amendment 单列不改原 scope；P2 首次 readonly 容器无法直接 docker cp，失败/未知 Job 保留，后续新试验使用不启动的输入容器物化文件，再在独立只读容器执行。原记录不覆盖。
