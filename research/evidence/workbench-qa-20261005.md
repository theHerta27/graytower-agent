# React 工作台与两题独立 QA 实施记录

日期：2026-10-05。V1 单机、loopback、SQLite；旧游戏与原始评测保持原样。当前可以实际操作配置候选确认、独立 QA 委托、报告及战斗取证。完整 M3、Electron、Coding 稳定 Runtime、Unity 可玩与自动测试、NPC 世界链仍未完成。

## 可运行的业务链

浏览器 `http://127.0.0.1:8765` 提供“配置提案”和“独立验证”。React/TypeScript 负责输入、差异、明确确认、进度与证据；Starlette 同源 API 复用现有 Config 图、候选领域、A2A 委托、独立 QA 图和 MCP 工具，没有新增 Agent 主循环。`workbench.sqlite` 只保存页面操作及候选索引；原 Job/请求账本和 checkpoint 继续各归其层。

实际浏览器操作先读取历史 1.55 候选，核对 1.4→1.55 并明确确认；查看真实旧报告的 1 条错误及单版本部分摘录。初始数据来自 `prepare_workbench_demo.py` 的只读复制，旧数据与账本未改。随后通过页面确认新冻结的 1.52、1.68 候选，依次填入完整冻结目标并执行真实 QA；运行中刷新页面继续查询同一个操作，未另建任务。

最终服务关闭模型。报告重放仍返回同一请求和结果，两题重放均 0 新调用、0 新战斗。候选确认不应用游戏配置。普通 UI 不提供调用上限、凭据、目录或审核规则的变更入口；本轮收费服务另受两题白名单、固定顺序、每题四次和总八次约束。

## 授权与容量验证

新题与评分冻结在 `research/evals/qa-independent-v1`，不使用 Config 确认集。候选由可信领域接口离线物化，不计为 Config 模型成绩。

首次零调用准备测得“两份 Trace＋配对摘要”需要约 25,083 字符，原拟 18,000 无法容纳。因此在任何模型运行前保留原准备目录，并生成 `local-data/qa-independent-v1-32k`：32,000 输入字符、2,048 输出 token、8 次/8 场、USD0.40。保守费用上界 USD0.331776。用户明确批准该具体 scope；题目、顺序、评分标准及调用/战斗上限不变。这是预检发现的容量调整，不是见到模型结果后放宽标准。

按[DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/)峰值估算：输入未缓存 USD0.30/M、缓存 USD0.006/M、输出 USD1.20/M。费用是基于 usage 的保守估值，不是账单。

独立助手复核文件为 `local-data/qa-independent-v1-32k/independent-review.json`，绑定原输出 hash、逐项原话与证据指针。复核者未编写题目、不是被测 DeepSeek，但参与过本项目后端开发；不是双盲或真人评审。完整审阅 7 次响应中的 **9 条决定、29 个子句**，未发现未支持主张；四个被引用的伤害值 221/331 对 184/276、结束 turn82/93、部分视图 19/905 和 19/1017 均核对到真实摘录。

两份报告均总体 INCONCLUSIVE、结构 PASS。这只说明两项窄业务目标的语义完成，不能证明总体 QA 质量、因果能力、多 Agent 质量收益或游戏总体改善。固定 seed7/11 已使用过；跨两题共四个配对但只有两种 seed，不冒充四个独立随机种子。

**不是两次规范无故障验收：** 虽然执行的策略/参数/预算均合法、报告中无运行错误，原 wire 在 `parallel_tool_calls=false` 下仍两次返回两个 Decision。LangChain 当时只取第一个，另一条计划未立即执行。第一题最终如实只读 baseline；第二题另一次正式决定才读取 baseline。计划不能当已执行证据，每题 `first_attempt_clean=false`，不能只看最后报告错误数组为零就宣布全通过。

总账：7 预留/7 完成、0 失败/0 未知；26,708 输入（11,520 缓存）＋1,673 输出，峰价估 **USD0.00663312**。8 场已执行，两题结束后剩余 1 次授权关闭，不转为补题、额外解释或挑选重跑。

## 修复与恢复边界

- 新模型网关检查恰好一条合法、正确名称的结构化调用。双调用、非法调用或错误名称会保存全部 raw/usage，记失败并停止该步，不再静默挑第一个。先以真实症状的离线 HTTP fixture 复现红测，再修复；**修复后的真实模型表现尚未验证**，原七次账本不改。
- 页面提交未到服务端时，原来会持续 404 并锁住 UI。现保存原始内容与同一 ID，提供原内容重试；不会生成另一个操作。报告读取失败后的“刷新”也会重新读取同一报告。两项均先复现红测后通过。
- 模型决定/checkpoint 已保存、报告提交前崩溃，原工作台在额度零时拒绝恢复。现允许已准入请求显式恢复；没有模型权限时用零调用预算，沿原 checkpoint/receipt 收尾。已启动却无 receipt 的作业仍拒绝恢复。测试保留原决定、原收据、原计费场数且不新增推理。
- 报告注明其绑定候选，避免左侧新委托选择与右侧已有报告混淆。模型意见单独标为未核验，不覆盖程序数值与总体结论。
